NVIDIA Auto Ontology: 데이터베이스 의미 계층과 자연어 SQL

DB 메타데이터를 업무 용어·SQL 속성·관계로 정리하고, 사람이 검토한 정의를 활용해 에이전트의 자연어 데이터 질의를 지원하는 Apache-2.0 프로젝트. 외부 모델 API와 데이터 보안 검토는 별도다.

#NVIDIA#온톨로지#Text-to-SQL#MCP#pgvector#데이터 거버넌스

무엇을 할 수 있나요?

스키마·열 프로파일·표본값을 카탈로그화하고 업무 용어, 컬럼 매핑, SQL 속성, 테이블 관계를 생성한다. 사람이 정의를 수정·인증하는 단계를 포함한다.

질문 의도와 개체 추출, 후보 검색, SQL 생성·검사·수정, DB 실행을 거쳐 SQL과 처리 과정을 돌려준다. 답할 수 없는 질문의 범위 확인도 제공한다.

웹 UI, 사용자 권한을 따르는 읽기 전용 MCP 도구, CLI·REST API 연계를 설명한다. PostgreSQL·MySQL·Snowflake·Databricks·DuckDB·SQLite 등 10개 엔진을 지원한다.

로컬 빠른 시작도 Docker Compose v2, uv, PostgreSQL+pgvector 및 모델 endpoint/key 설정이 필요하다. 백엔드·인제스트는 Python 3.12+, 프런트는 Next.js 계열이다.

기본은 NVIDIA hosted NIM이지만 자체 호스팅 NIM 또는 OpenAI-compatible endpoint로 역할별 교체할 수 있다. structured output 지원 모델과 동일한 인제스트/질의 임베딩 모델이 필요하다. ChatGPT·Hermes 등의 구독 로그인만으로 이 API 조건이 충족된다고 보지 않는다.

공식 평가 저장소는 같은 모델을 사용한 schema-only 대조군과 ontology agent 처리군의 SQL 실행 정확도를 비교한다. 읽은 문서에서 보편적 정확도 향상 수치를 확인하지 않았으며 별도 실험을 실행하지 않았다.

실제 LICENSE는 Apache-2.0이다. 모델 endpoint, KumoRFM, 원천 DB 및 제3자 의존성의 약관·라이선스·비용은 별도로 검토해야 한다.

살펴볼 점
  • 자료 원문만 확인했다. 설치·서버 기동·질의 실행·추론·모델 API 호출·계정 변경을 하지 않았다. 업무·교육 현장 효과를 검증한 자료로 해석하지 않는다.
  • 기본 모델 endpoint는 외부 hosted 서비스다. 질의·문맥과 임베딩/리랭킹 입력이 설정한 endpoint로 전송되는 구조이므로 DB가 로컬에 있다는 이유만으로 개인정보가 외부로 나가지 않는다고 보장할 수 없다. 학생·교직원 개인정보가 포함된 원본 DB를 연결하지 말고 기관 검토·비식별화·최소 권한을 먼저 적용해야 한다.
  • 선택적 KumoRFM 예측은 KUMO_RFM_API_KEY를 설정할 때 연결 테이블을 hosted 서비스로 업로드한다. 기본 테이블 상한 20개, 행 상한은 미설정 시 무제한이다.
  • Vault 미설정 또는 일부 값만 설정하면 연결 비밀번호가 Postgres에 평문 저장된다. 3001·3002는 공개 노출하지 않으며 기본 비밀번호·비밀값도 교체해야 한다.
  • 일부 DB probing 검사는 .env.example에서 기본 꺼짐으로 설명한다. 생성 SQL과 업무 정의를 사람이 검토해야 하며 검증 기능만으로 정답·접근 통제가 보장되지 않는다.
  • 평가 대조군은 no-tools 단일 프롬프트, 처리군은 retrieval agent다. 선택적 exemplars/anchors를 켠 실험은 온톨로지 외 추가 도움 효과도 포함한다. 수치가 생겨도 해당 데이터·모델·설정 범위를 벗어나 일반화하지 않는다.
  • README의 앞부분과 후반 모델 표에 기본 임베딩·리랭커 명칭 차이가 있다. 실제 배포 시 .env.example와 해당 버전을 확인한다.
