Netlify 크레딧 관리: 미리보기와 운영 배포를 분리하기

Credit-based Free 플랜은 월 300크레딧, 성공한 운영 배포는 회당 15크레딧이다. 작은 수정마다 공개하기보다 로컬·미리보기 검증 후 묶어서 배포하고 팀 전체 사용량을 확인한다.

#Netlify#배포#비용 관리#커뮤니티 인사이트

무엇을 할 수 있나요?

먼저 계정의 실제 요금제가 Credit-based인지 확인한다. 공식 문서 기준 Free 플랜은 월 300크레딧의 hard limit이고 자동 충전이 없다. 크레딧이 소진되면 팀의 모든 웹 프로젝트가 일시 중지되어 방문자에게 Site not available 화면이 표시된다.

성공한 production deploy는 회당 15크레딧이다. Deploy Preview·branch deploy의 배포 자체, 실패한 배포, 이전 운영 배포로의 롤백은 배포 크레딧을 소비하지 않는다. 다만 미리보기와 브랜치에서도 트래픽 요청은 과금 대상이므로 전체 사용이 무료라는 뜻은 아니다.

작업 흐름은 로컬 수정·테스트, 미리보기 검토, 변경사항을 한 릴리스로 묶기, 승인된 버전 운영 배포 순서로 분리한다. 에이전트에는 운영 배포를 명시적인 최종 단계로 두고 Git 푸시만으로 배포되는 연결도 확인한다.

배포 외에 대역폭·웹 요청·컴퓨트·AI 추론이 같은 잔액을 사용한다. 공식 문서는 대역폭 1GB당 20, 웹 요청 1만 회당 2, 컴퓨트 1GB-hour당 10, AI 모델 사용 1달러당 180크레딧을 안내한다. 따라서 300÷15를 실제 보장 배포 횟수로 해석하지 않는다.

월간 크레딧은 각 계정의 billing cycle 시작 시 초기화된다. 특정 요일이나 매월 1일에 모든 계정이 같이 복구된다고 가정하지 말고 관리 화면의 사용량과 갱신일을 확인한다.

살펴볼 점
  • 2026-11-09 공식 문서 기준으로 정리했으며 기존 요금제·Enterprise·프로모션 조건에는 차이가 있을 수 있다. 적용 전 자신의 플랜과 최신 가격을 확인한다.
  • 실제 계정의 과금·한도·복구 동작을 시험하거나 유료 플랜을 신청하지 않았다.
  • Personal·Pro의 auto recharge는 비용을 추가 청구하는 기능이다. 사이트 중단을 피하려고 사용자 동의 없이 켜지 말고 예산과 팀 전체 적용 범위를 먼저 검토한다.
