Codex 서브에이전트: 동시 실행 개수와 모델·추론 강도 설정 확인법

요청한 에이전트 수와 동시에 열리는 스레드 수는 다르다. Codex 공식 문서 기준 동시 실행 상한 설정 키와 서브에이전트 모델 지정 방법 정리

#Codex#서브에이전트#config.toml#병렬 작업#토큰 관리

무엇을 할 수 있나요?

Codex 공식 문서는 서브에이전트 작업이 기본으로 켜져 있으며, 사용자가 직접 요청하거나 AGENTS.md·스킬 지침이 요청할 때 작업을 나눠 맡긴다고 설명합니다. 각 서브에이전트가 따로 모델과 도구를 쓰므로 단일 에이전트보다 토큰을 더 소비합니다.

동시에 열 수 있는 서브에이전트 스레드 수는 `config.toml`의 `[agents]` 아래 `max_concurrent_threads_per_session`으로 제한하며, 기존 설정의 `max_threads`는 이전 이름(별칭)으로 계속 쓸 수 있습니다. 값을 비워 두면 Codex가 기본값을 정한다고 되어 있어, 에이전트를 10개 요청해도 동시에 도는 수는 이 상한에 따라 달라질 수 있습니다.

서브에이전트의 모델과 추론 강도를 따로 정하지 않으면 부모 세션 설정을 물려받습니다. `[agents]`의 기본 모델·추론 강도나 `~/.codex/agents/`, `.codex/agents/`에 둔 사용자 정의 에이전트 TOML 파일로 역할별(탐색·검토·수정) 모델과 샌드박스를 다르게 지정할 수 있습니다.

공식 문서는 읽기 위주 작업(탐색·테스트·로그 분석·요약)부터 병렬화하고, 여러 에이전트가 동시에 코드를 고치는 작업은 충돌 위험이 커지므로 신중하라고 권합니다. 좋은 요청문에는 작업 분할 방식, 모두 기다릴지 여부, 돌려받을 요약 형식을 적습니다.

살펴볼 점
  • 동시 실행 기본값은 버전과 환경에 따라 다를 수 있고 공식 문서도 고정 숫자를 제시하지 않습니다. 커뮤니티에서 도는 '기본 3개' 같은 숫자를 사실로 단정하지 말고 본인 설정과 앱 표시를 확인하세요.
  • 이 카드는 공식 문서 확인이며, 동시 실행 개수에 따른 속도·비용 측정은 하지 않았습니다.
