Laya: 텍스트를 생성하지 않는 오픈 웨이트 판단 모델

문서·메일·티켓·JSON을 입력받아 예/아니오·선택·점수형 질문을 한 번의 순전파로 판정하는 소형 System 1 모델군

#Laya#System 1#오픈 웨이트#다국어

무엇을 할 수 있나요?

핵심 원리: Laya는 문장을 새로 생성하지 않고 주어진 상태(state)에 대해 예/아니오, 선택지, 점수 같은 형식화된 답과 확률을 반환합니다. 고객 문의 분류, 긴급도·이탈 위험 판정, 에이전트 다음 행동 선택처럼 생성보다 빠른 구조화 판단이 필요한 파이프라인을 겨냥합니다.

모델 구성: 영어용 ModernBERT-large 기반 421M 모델, 100개 이상 언어를 대상으로 한 mmBERT-base 기반 322M 모델, 특정 typed-decisions 작업용 파인튜닝 체크포인트를 한 저장소에서 제공합니다. 가중치와 코드는 Apache 2.0이며 `pip install laya` 후 Router 또는 단일 모델 SDK로 실행합니다.

권장 사용법: Router는 입력의 문자 체계와 언어를 먼저 감지해 영어·다국어 체크포인트를 자동 선택합니다. 서버에서는 필요한 체크포인트를 미리 로드해 언어가 바뀔 때마다 모델을 다시 읽는 지연을 피하고, 실제 업무 데이터로 정확도·확률 보정·오탐 비용을 측정한 뒤 자동화를 확대합니다.

적용 예시: 이메일·지원 티켓을 담당 부서로 보내고, 환불 요청·취소 위험·긴급도를 동시에 판정하거나, AI 에이전트의 툴 호출을 허용·차단·검토 대기로 나누는 1차 라우터로 사용할 수 있습니다.

살펴볼 점
  • 모델 카드가 명시하듯 기본 체크포인트는 typed-decisions 벤치마크에서 제로샷 성능이 다수 클래스 기준보다 낮았습니다. 높은 수치는 해당 학습 분할로 파인튜닝한 체크포인트의 결과이므로 범용 성능으로 일반화하면 안 됩니다.
  • 선택지가 매우 많을 때는 기본 토큰 예산 때문에 정확도가 크게 떨어질 수 있고, 확률도 과신하는 경향이 있어 자체 데이터로 온도 보정과 단계형 분류를 검토해야 합니다.
  • 지연 시간과 Jev 비교 수치는 제작자 모델 카드와 서로 다른 제3자 벤치마크를 조합한 값입니다. 동일 환경의 독립 비교로 간주하지 마세요.
