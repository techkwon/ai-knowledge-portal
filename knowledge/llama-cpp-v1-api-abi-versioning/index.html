llama.cpp v1.0: 로컬 AI 라이브러리의 API·ABI 변경 추적

llama.cpp·ggml이 공개 C API와 ABI의 호환성 경계를 메이저 버전으로 드러내고, 호환 기능 추가와 버그 수정을 구분하는 릴리스 정책을 발표했다.

#llama.cpp#ggml#API#ABI#버전 관리

무엇을 할 수 있나요?

ggml-org 공식 글은 libllama와 libggml v1.0.0을 발표하고, 이후 API·ABI 비호환 변경을 메이저 버전 변경으로 표시한다고 설명한다. 버전표의 구체적 MAJOR 기준은 ./include의 공개 C API 변경이다.

MINOR는 하위 호환 기능·백엔드 갱신·모델 지원·API 추가, PATCH는 API 변경이 없는 버그 수정이다. 로컬 AI 앱을 유지보수할 때 모델 파일 버전과 추론 라이브러리 버전을 따로 기록하고, 메이저 갱신 전 연결 코드의 호환성을 검토하는 근거가 된다.

공식 배포 안내는 사전 배포 산출물·Docker·패키지 관리자·XCFramework 등을 플랫폼별로 나눈다. 운영체제가 목록에 있다는 사실과 특정 모델이 현재 기기의 메모리·백엔드에서 실행된다는 사실은 다르다.

llama.cpp LICENSE의 MIT 본문은 사용·복제·수정·배포·판매 등을 허용하되 저작권 및 허가 고지 보존과 무보증을 규정한다. 이는 별도로 받는 모델 가중치·데이터·연결 서비스의 권리를 대신하지 않는다.

살펴볼 점
  • 공식 글과 llama.cpp 코드 LICENSE 본문만 읽었다. 설치·API 호출·빌드·속도 측정·호환성 실험은 하지 않았다.
  • 로컬 처리 가능성이 개인정보의 완전한 보호나 외부 통신 부재를 뜻하지 않는다. 앱·플러그인·로그·모델 다운로드 경로와 학교 정책을 따로 점검해야 한다.
  • 런타임 코드의 MIT 조건은 모델 이용 연령·미성년자 대상 서비스·입력 데이터 이용 허가를 정하지 않는다. 모델·호스팅 API 및 배포 대상별 약관을 별도로 확인해야 한다.
  • 모든 모델이 모든 기기에서 같은 기능·성능으로 실행된다는 보장이 아니다. ggml 자체 LICENSE 전문은 이번에 별도로 읽지 않았다.
