LangChain 페이드미디어 에이전트: 스킬과 위키를 분리한 실전 설계

LangChain이 자사 마케팅팀에 배치한 에이전트에서 계산은 코드로, 판단은 모델로 넘기고 재사용 가능한 스킬과 회사 고유 지식(위키)을 분리한 실전 운영 사례

#실무 가이드#LangChain#에이전트 설계

무엇을 할 수 있나요?

핵심 원리: LangChain은 자사 유료광고 운영 에이전트를 만들며 반복 가능한 계산·규칙은 코드로 처리하고, 원인 분석과 다음 행동 제안처럼 판단이 필요한 부분만 모델에 맡겼습니다. 초기 버전은 모든 걸 모델에 맡겨 보고서 1건에 약 390만 토큰을 소모했는데, 계산을 코드로 옮긴 뒤 같은 작업이 약 40배 저렴하고 13배 빨라졌습니다.

절차: 시스템 프롬프트·스킬·위키·실시간 도구·결정론적 코드 5개 계층으로 맥락을 나눕니다. 스킬은 "다른 회사에서도 통하는" 재사용 가능한 작업 방식만 담고, 회사 고유 정보(캠페인 목적, 과거 결정 이유 등)는 위키에 둡니다. 매 데이터 지표마다 신뢰할 단일 출처 시스템을 정하고, 그 출처 밖 도구는 에이전트에서 아예 제거해 잘못된 조회를 막습니다.

예시: 서브에이전트 격리 설계에서 두 플랫폼 담당 서브에이전트가 같은 파일 경로와 완료 플래그를 공유해 한쪽이 먼저 끝나면 다른 쪽이 멈추는 문제를 겪었고, 플랫폼별로 별도 저장 경로와 완료 상태를 부여해 해결했습니다. 도구 탐색도 200개 넘는 광고 플랫폼 도구를 한 번에 로드하는 대신 검색→스키마 조회→실행 3단계 인터페이스로 바꿔 첫 턴 토큰을 4배 줄였습니다.

적용 조건: 여러 데이터 소스·플랫폼을 다루며 판단과 계산이 섞인 반복 업무(운영 보고, 주간 분석 등)에 적합합니다. 사람이 변경을 승인하는 게이트를 두고, 모델은 분석과 제안까지만 담당하게 설계했습니다.

살펴볼 점
  • 이 사례는 LangChain의 자체 마케팅 운영에 맞춘 설계이며 수치(비용 절감률, 토큰 감소율)는 해당 조직의 특정 워크로드 기준입니다. 다른 도메인에 그대로 적용하면 결과가 달라질 수 있습니다.
  • LangSmith Sandbox, Deep Agents 등 특정 벤더 도구를 전제로 한 구현 세부사항이 포함되어 있어, 다른 프레임워크에서는 아키텍처 원칙만 참고하고 세부 구현은 별도로 검증해야 합니다.
