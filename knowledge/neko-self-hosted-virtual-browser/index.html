Neko: Docker로 띄우는 셀프호스팅 공유 가상 브라우저

WebRTC 기반으로 컨테이너 안에서 브라우저(또는 데스크톱)를 스트리밍해, 여러 사람·에이전트가 동시에 접속해 화면을 함께 보고 제어권을 넘겨받아 조작할 수 있는 오픈소스 셀프호스팅 프로젝트

#Docker#WebRTC#오픈소스#원격 브라우저

무엇을 할 수 있나요?

공식 GitHub README에 따르면 Neko는 Docker 컨테이너 안에서 브라우저를 실행하고 WebRTC로 화면을 스트리밍해, 여러 사용자가 동시에 접속할 수 있게 하는 셀프호스팅 오픈소스 프로젝트입니다. 공식 UI 문서(neko.m1k1o.net/docs/v3/customization/ui)는 한 번에 화면을 제어하는 사람이 있고 다른 참가자는 보면서 제어권을 요청해 넘겨받는 방식으로 조작을 공유한다고 설명합니다.

브라우저에만 한정되지 않고 Linux에서 실행되는 어떤 프로그램(예: VLC)이나 전체 데스크톱 환경(XFCE, KDE 등)도 같은 방식으로 스트리밍할 수 있다고 설명합니다.

공식 문서가 제시하는 활용 예로는 공동 시청(watch party), 인터랙티브 발표, 공동 브라우징·디버깅, 세션 녹화/방송, VPN 없는 내부 애플리케이션 접근(jump host), 그리고 Playwright·Puppeteer를 설치해 자동화 작업을 수행하면서 실시간으로 개입할 수 있는 '자동화된 브라우저' 용도가 있습니다.

다중 사용자 룸 관리가 필요하면 별도 프로젝트인 neko-rooms를 함께 쓸 수 있으며, HTTPS를 포함한 설치 가이드도 공식 문서(neko.m1k1o.net)에서 제공합니다.

살펴볼 점
  • AI 에이전트에게 '공유 가능한 브라우저'를 주는 용도로 커뮤니티에서 언급되었으나, 이는 사용 사례 제안일 뿐 공식 문서가 에이전트 연동을 전제로 설계된 것은 아니며, 이 글도 실제 설치·연동 테스트를 거치지 않았습니다.
  • 공식 README의 연결 종료 후 호스트 브라우저에 상태가 남지 않는다는 설명은 접속자 쪽 브라우저를 가리킵니다. 서버의 프로필 볼륨은 북마크 등 프로필 파일을 보존할 수 있지만, 기본 브라우저 정책은 종료 시 쿠키·세션을 지웁니다. 로그인 상태를 재시작 후에도 유지하려면 볼륨뿐 아니라 관련 정책도 조정해야 합니다. 설정에 따른 서버 데이터 보존과 공유 세션 접근권한·민감 계정 노출을 함께 검토해야 합니다.
