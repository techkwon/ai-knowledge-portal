Hermes Agent Advanced Delegation: 서브에이전트에 모델/프로필 라우팅 추가하기

Hermes Agent 공식 플러그인으로, 기존 단일 delegation 모델 대신 작업별로 이름이 붙은 모델 라우트(model_map) 또는 프로필 라우트(profile_routes)를 골라 서브에이전트를 실행할 수 있게 하는 공식 확장

#Hermes Agent#서브에이전트#delegation#Nous Research#플러그인

무엇을 할 수 있나요?

핵심 원리: 기본 Hermes는 delegation.model/provider를 사용하고 설정이 없으면 부모 모델을 따릅니다. 플러그인은 model_map(사전 등록한 fast/deep/local 등의 모델 경로)과 profile_routes(다른 Hermes 프로필의 모델·자격증명·스킬·SOUL.md) 중 한 모드를 활성화합니다. 라우트를 선택하지 않은 작업은 해당 모드의 기본 라우트를, 이것도 없으면 부모 모델을 사용합니다. 두 확장 모드에서는 기본 delegation.model/provider 설정을 사용하지 않습니다.

사용 절차: Hermes 0.22.5 이상에서 `hermes plugins install advanced-delegation`으로 설치한 뒤 `hermes delegation config`로 모드와 라우트를 등록합니다. 설치·설정은 작업을 위임하는 프로필별로 하며 대상 프로필은 작동하는 모델 설정을 갖추면 됩니다. `/delegation model_map` 등으로 저장한 변경은 기본적으로 다음 세션(`/new`)부터 적용됩니다. 지원되는 Hermes에서 `--now`로 현재 대화에도 적용할 수 있지만 도구 스키마가 바뀌어 프롬프트 캐시가 한 번 끊기고 다음 요청 비용이 늘 수 있습니다.

활용: 작업에 따라 사전 등록한 저비용·고성능·로컬 모델 경로를 고르거나 다른 프로필의 설정으로 서브작업을 실행할 때 쓸 수 있습니다. 공급자 경로는 이미 구성된 자격증명을 사용하며, 경로의 원시 키·엔드포인트를 모델이 자유롭게 만들어 도구 인자로 넘기는 방식은 아닙니다. 프로필 선택 자체를 안전한 OS 격리로 과신하지 말고, 대상 프로필이 상속하는 자격증명과 터미널 권한을 확인해야 합니다.

살펴볼 점
  • Profile routes는 나열된 프로필의 자격증명·크리덴셜 풀·SOUL.md·터미널 정책까지 서브에이전트가 그대로 쓰게 되므로, 키·터미널 접근을 믿고 맡길 프로필만 등록해야 한다고 공식 경고가 명시되어 있습니다.
  • Hermes 0.22.0~0.22.4는 설치 자체가 거부되고, 0.22.0 미만에서는 설치는 되지만 동작하지 않고 경고만 남깁니다.
  • 직접 설치·구성 실행은 하지 않았으며 공식 문서 내용만 확인한 것입니다.
