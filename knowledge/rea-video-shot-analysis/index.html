rea-video: 영상을 샷별 제작 증거와 재제작 계획으로 분해

참조 영상을 촬영·AI 생성·3D·코드·화면녹화 등의 샷으로 분석하고 자막·음향·재제작 경로를 보고서로 만드는 Apache2.0 도구. 진위 판정 보증이나 원클릭 완성 영상 생성기는 아니다.

#rea-video#영상 분석#샷 분해#미디어 리터러시#Python#Apache-2.0

무엇을 할 수 있나요?

어떤 도구인가: 장면 전환·프레임·노이즈·메타데이터와 선택적 시각언어모델의 관찰을 묶어 샷별 제작방식·촬영·조명·자막·편집·음향을 설명하고 재제작 계획을 제시한다. 역추정 프롬프트는 원본 프롬프트 복구 보증이 아니다. 읽은 README에서 별도 학술논문은 확인하지 못했고 저장소 문서·코드·자체평가가 근거다.

실행 조건: Python 3.10 이상과 ffmpeg, numpy·OpenCV·Pillow·PyYAML·ONNX Runtime이 필요하고 OCR은 선택 의존성이다. 에이전트가 CLI를 호출하는 흐름이며 기본 로컬 분석의 GPU 필수 조건은 확인되지 않았다. 음원 분리는 CPU 코드이고 첫 실행에 약 67MB 보조모델을 자동 다운로드하므로 처음부터 완전 오프라인이라는 뜻은 아니다.

출력: breakdown.json, HTML/Markdown 보고서, storyboard.jpg, 샷 프레임, SRT/ASS 자막·편집 타임라인을 문서가 명시한다. 생성 보고서와 상세 문서는 현재 중국어이며 사용자 언어 설명은 별도 에이전트에 의존한다.

비용과 외부모델: 기본 도구 분석은 로컬에서 수행하며 공급자는 무료라고 안내한다. VLM을 쓰려면 OpenAI 호환 API 주소·키·모델이 필요하고 모델 사업자 요금이 별도다. 구독 OAuth 로그인만으로 API 키가 제공된다고 가정하면 안 된다. 별도 capsule-cinema 영상 생성도 별도 설치·모델·비용이 필요하다.

자동화 범위: 본체는 분석·계획 도구다. 실사는 직접 촬영하고 코드/Remotion은 에이전트가 작성해야 한다. 문서는 AI 샷 생성과 정적 이미지 이동의 일부 재구성을 지원하나 자동 검증은 부분 구현, Remix는 미착수로 구별한다. README와 복제 문서 간 완전 자동화 설명이 달라 일괄 완성 영상을 보장하지 않는다.

라이선스: 실제 LICENSE와 NOTICE는 Apache 2.0이다. 라이선스·저작권/NOTICE 보존·수정 표시 등의 조건 아래 코드 이용이 가능하다. 자동 다운로드되는 UVR 음원 분리 가중치와 외부 영상 모델에는 별도 조건이 있을 수 있고 이번에 그 보조 가중치의 라이선스까지 확정하지는 못했다.

살펴볼 점
  • 설치·CLI 실행·영상 추론·API 호출·성능 재현을 하지 않았다. GPU 최소사양과 처리시간은 직접 검증하지 않았다.
  • 자체평가의 98~100%는 소규모 특정 데이터의 샷 길이 가중 지표다. 평가 문서 스스로 일부 holdout에 맞춘 규칙 수정과 비독립성을 고지한다. 압축·재인코딩으로 노이즈 증거가 사라지고 음악 출처·효과음 분리는 취약하므로 딥페이크 확정·증거 감정·사람에 대한 판정에 쓰지 않는다.
  • VLM 옵션의 실제 코드는 키프레임과 영상 클립을 외부 API에 전송한다. 로컬 파일 경로를 넣었다고 계속 로컬에만 머무는 것이 아니다. 학생 얼굴·음성·비공개 화면이 있는 영상을 권한 없이 전송하지 않는다.
  • 원본 영상·음악·캐릭터·초상의 권리를 확보해야 한다. 비교 데모 공개는 원본 재업로드·음악 재사용·상업 복제 허가가 아니다. 소스코드의 Apache 2.0과 미디어·보조 가중치 권리를 분리해서 판단한다.
  • H3를 이용한 재제작 데모 설정은 필수조건이 아니다. 해당 영상 모델을 따로 쓸 때에는 한국 등 지역 제한을 포함한 모델별 라이선스와 AI 표시 조건을 별도로 확인해야 한다.
  • 선택한 외부 endpoint 사업자의 입력·영상 보관 기간, 학습 이용, 재위탁·국외 이전 조건은 별도로 확인해야 한다. 외부 API 연결의 존재를 보관·학습 미사용 보증으로 해석하지 않는다.
