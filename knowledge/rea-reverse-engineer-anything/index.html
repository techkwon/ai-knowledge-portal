REA: 바이너리·앱·웹 기능을 분석해 재현하는 리버스 엔지니어링 MCP

원하는 앱 기능을 소스 코드 없이 네이티브 바이너리·JS/Electron 앱·웹에서 분석해 증거와 함께 설명하고 재구현을 돕는 에이전트 도구

#실무 가이드#MCP

무엇을 할 수 있나요?

공식 저장소 설명에 따르면 REA는 Claude Code·Codex·Cursor·Gemini CLI 등 여러 에이전트에 MCP 서버와 워크플로 지침을 등록해, '이 기능이 어떻게 동작하는지 분석해서 내 프로젝트에 비슷하게 만들어줘' 같은 요청을 처리합니다.

네이티브 바이너리 분석은 Hopper·Ghidra·IDA 같은 기존 분석 엔진을 연결해서 쓰고, 정적 JavaScript/Electron 앱 분석은 별도 엔진 없이 동작한다고 설명합니다. 분석은 로컬에서 실행되며 결론마다 근거와 한계를 함께 제시한다고 공식 문서에 적혀 있습니다.

설치는 `npx rea-agents setup` 한 줄로 에이전트에 등록하고, 터미널에서 ASAR/추출된 앱 디렉터리를 바로 분석하는 CLI(`rea`)도 별도로 제공합니다.

살펴볼 점
  • 공식 문서는 IDA Pro·Hopper·JEB 같은 상용 분석 도구의 라이선스를 REA가 대신 제공하지 않으며, 정식 라이선스 없이 크랙본이나 탈취한 키를 쓰는 것은 허용되지 않는다고 명시합니다.
  • 리버스 엔지니어링 결과로 만든 재구현물의 저작권·라이선스·이용약관 준수 여부는 분석 대상 앱의 약관에 따라 별도로 검토해야 하며, 이 도구가 법적 판단을 대신하지 않습니다.
  • 공식 문서는 정적 JavaScript/.NET 분석은 파일을 읽기만 하지만, 프로세스 동작·Android 기기·브라우저 캡처 같은 '런타임' 분석은 사용자 권한으로 대상 프로그램을 실제로 실행·조작한다고 구분합니다. 또한 분석 자체는 로컬에서 실행되지만 그 결과(도구 호출 결과)는 에이전트로 전달되어 에이전트가 쓰는 모델 제공자의 별도 데이터 정책을 따른다고 FAQ에서 명시합니다.
