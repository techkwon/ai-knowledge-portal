GPT-6 프롬프트 캐싱: 30분 재사용 할인과 캐시 미스 진단 도구

장시간 에이전트의 반복 컨텍스트 비용을 줄이는 OpenAI의 향상된 프롬프트 캐싱. 30분 재사용 기준, 명시적 중단점, 대시보드·진단 도구, 캐시를 깨지 않는 도구·지침 관리법 정리

#OpenAI#GPT-6#프롬프트 캐싱#Responses API#에이전트 비용

무엇을 할 수 있나요?

OpenAI 공식 발표(2026-09-22)에 따르면 GPT-6 제품군과 함께 기본 캐시 적중률을 높인 프롬프트 캐싱 시스템이 도입됐습니다. 여러 요청이 같은 지침·도구 정의·이전 대화를 앞부분(접두부)으로 공유하면, 30분 이내에 재사용되는 적격 공유 접두부에 캐시 할인이 적용되며 캐시된 입력 토큰은 최대 90%까지 할인됩니다.

공식 프롬프트 캐싱 가이드의 비교표 기준으로 GPT-5.6 이후 모델은 캐시 읽기가 일반 입력 단가의 0.1배, 캐시 쓰기가 1.25배이며, 수명은 `prompt_cache_options.ttl`의 `30m`(기본값)으로 마지막 쓰기·재사용 뒤 최소 30분입니다. 한 번 쓰고 여러 번 읽을수록 절감 폭이 커집니다.

새 도구로 프롬프트 캐싱 대시보드(시간별 적중률, 캐시된/미캐시 토큰 비율)와 진단 도구가 제공됩니다. 진단 결과는 예를 들어 `tools_changed`처럼 무엇이 바뀌어 재사용이 막혔는지와 영향받은 토큰 수를 알려 줍니다.

캐시를 지키는 요령: 명시적 캐시 중단점으로 재사용할 접두부를 고르고 자주 바뀌는 내용은 프롬프트 끝에 둡니다. 도구 정의·스키마·순서는 그대로 두고 `allowed_tools`로 호출 가능한 도구만 제한하거나 필요 없을 땐 tool_choice를 none으로 둡니다. 지침을 바꿀 때는 기존 지침을 고치지 말고 새 개발자 메시지를 끝에 덧붙입니다. 알려진 공통 컨텍스트는 사전 준비(prewarm)로 미리 캐시할 수 있고, GPT-6에서는 `configuration_update`로 대화 중 추론 강도를 바꿔도 캐시가 유지됩니다.

살펴볼 점
  • '비용 90% 절감'은 전체 비용이 아니라 캐시된 입력 토큰에 대한 최대 할인입니다. 캐시 쓰기 요금이 붙는 모델이 있고, 세션을 유지한다고 캐시 적중이 보장되지는 않습니다. 모델 세대별 규칙이 달라 공식 가이드의 비교표를 먼저 확인하세요.
