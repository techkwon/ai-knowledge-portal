Harness²: 모델은 고정하고 에이전트 하니스를 재귀적으로 개선하는 프레임워크

시스템 프롬프트·가드레일·메모리·도구 가이드·서브에이전트·스킬·스크립트·플러그인 8가지 하니스 구성요소를 작업별로 제안-검증-합성(Propose-Probe-Compose)하며 반복 개선하는 Google Research 공식 오픈소스 프레임워크

#에이전트 하니스#재귀적 개선#Google Research#OpenCode#Codex

무엇을 할 수 있나요?

핵심 원리: 모델 가중치는 그대로 두고 에이전트 주변의 "하니스"(프롬프트, 도구, 메모리, 스킬, 오케스트레이션 등)만 최적화합니다. 작업 단위 재귀는 같은 작업에 대해 여러 수정안을 제안하고 실행해 그 결과를 대조한 뒤 더 나은 하니스를 합성하며, 상위 수준 재귀는 채택된 하니스와 근거 있는 교훈을 영구 "개선 하니스"에 누적해 다음 작업에 활용합니다.

구성: 시스템 프롬프트, 가드레일, 메모리, 도구 가이드, 서브에이전트, 스킬, 스크립트, 플러그인 등 8가지 편집 가능한 하니스 구성요소를 다룹니다. OpenCode 또는 Codex를 실행기로 선택할 수 있고, 병렬 재귀(여러 후보를 넓게 탐색)와 순차 재귀(한 하니스를 깊게 반복 개선) 두 모드를 지원합니다.

검증: 공식 저장소가 제공하는 JobBench(전문 업무), LAB(법률 업무), WorkBuddy-Bench(오피스·웹·코드) 세 가지 벤치마크에서 GLM-5·Gemini 3.5 Flash 기준 하니스 대비 개선(WorkBuddy-Bench 최대 11.5점, JobBench 4.5점, LAB 부분 통과율 11.8%p)을 공식적으로 보고합니다. 저장소에 로컬 데모(`harness2-demo`)가 포함되어 모델 자격증명 없이도 두 재귀 모드를 체험할 수 있습니다.

활용: 반복적인 업무 자동화에서 "어떤 프롬프트/스킬/메모리 조합이 더 나은가"를 시행착오로 수작업 조정하는 대신, 같은 작업을 여러 하니스 변형으로 실행해 결과를 비교하고 교훈을 축적하는 체계적 방법론으로 참고할 수 있습니다.

살펴볼 점
  • Google의 공식 지원 제품이 아니며("This is not an officially supported Google product"), Google Open Source Software Vulnerability Rewards Program 대상도 아닙니다.
  • 벤치마크 수치는 공식 저장소가 자체 보고한 것으로, 독립 재현 검증은 이루어지지 않았습니다.
  • 모델 호출이 포함된 벤치마크 실행은 API 비용이 발생하며, 실행기(OpenCode/Codex)의 네트워크 접근이 기본적으로 제한되지 않아 평가 전 네트워크 제한 설정이 필요하다고 공식 문서가 명시합니다.
