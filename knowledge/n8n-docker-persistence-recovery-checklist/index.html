n8n Docker 복구 점검표: 재설치보다 볼륨·암호화 키 확인

자동화 환경이 다시 초기 설정으로 돌아갈 때 컨테이너·영구 저장소·암호화 키를 분리해 확인하고, 삭제 전 전체 백업을 확보하는 안내입니다.

#n8n#Docker#백업#데이터 보존

무엇을 할 수 있나요?

1. 현재 실행 중인 컨테이너와 접속 포트를 먼저 확인합니다. 다른 인스턴스에 접속한 것인지, 저장 폴더가 연결되지 않은 것인지 구분하고 삭제·초기화를 서두르지 않습니다.

2. Docker의 /home/node/.n8n이 의도한 영구 볼륨에 연결됐는지 확인합니다. 공식 설명상 이 폴더에는 기본 SQLite 데이터베이스와 자격 증명 암호화 키가 저장된 config 등이 있습니다.

3. 복구 전 .n8n 폴더를 백업합니다. SQLite를 복사할 때는 n8n을 멈추거나 일관된 스냅샷 방식을 사용합니다. PostgreSQL·외부 파일 저장소를 쓰면 그 저장소도 함께 백업해야 합니다.

4. 기존 암호화 키와 배포 설정을 유지한 채 복원합니다. CLI workflow·credential 내보내기는 전체 인스턴스 백업과 다릅니다. 사용자·실행 이력·설정·암호화 키를 포함하는지 별도 확인하세요.

5. 재시작 후 기존 워크플로와 연결이 유지되는지 확인하고 작은 테스트를 통과한 뒤 운영을 재개합니다. 예를 들어 알림 워크플로 하나로 재시작 전후 상태를 비교하는 점검을 계획할 수 있습니다.

살펴볼 점
  • 컨테이너 재시작과 컨테이너 재생성·볼륨 삭제를 구분해야 합니다. 영구 볼륨이 없거나 다른 볼륨을 쓰면 데이터가 없는 것처럼 보일 수 있습니다.
  • 로그인 실패·요금 화면·429 오류를 모두 데이터 손실로 단정하지 마세요. HTTP 상태·로그·접속한 서비스와 계정을 각각 확인해야 합니다.
  • 암호화 키나 평문 credential 내보내기는 민감정보입니다. 공개 저장소에 넣지 마세요. 이 안내에 따라 실제 복구 테스트를 수행한 것은 아닙니다.
