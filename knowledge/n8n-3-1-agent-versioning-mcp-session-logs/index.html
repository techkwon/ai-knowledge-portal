n8n 3.1.0: 에이전트 게시 버전 분리와 MCP 세션 로그 조회

에이전트의 수정 중 초안과 운영 게시본을 분리하고, 버전 이력·게시 타임라인 및 읽기 전용 MCP 로그 도구로 테스트 결과와 실패 원인을 추적하는 업데이트입니다.

#n8n#3.1.0#MCP#에이전트 버전 관리#세션 로그#디버깅

무엇을 할 수 있나요?

2026년 11월 3일 릴리스된 n8n 3.1.0에는 버그 수정 외에 에이전트 버전 관리와 MCP 세션 로그 조회 기능이 명시돼 있습니다. 일반 워크플로 이력과 동일시하지 않고 Agent 운영·검증 기능으로 구분해 볼 업데이트입니다.

에이전트 설정이나 참조하는 skill 내용이 바뀌면 초안 버전을 저장하고, 저장된 이력 조회·복구·버전 이름과 설명 편집·선택 버전 게시를 지원합니다. 게시 타임라인에는 누가 언제 게시했고 어느 기간 활성 상태였는지 표시합니다. 이전 버전을 복구하면 새 초안이 만들어지는 방식입니다.

수정 중인 최신 초안이 있어도 별도로 저장된 버전을 게시할 수 있습니다. 예를 들어 V2를 수정 중인 상태에서 V1을 게시하면 운영은 V1을 사용하고 편집기의 V2 초안은 보존합니다. 게시 과정은 선택 버전의 완성도와 skill 접근권한을 검증합니다.

MCP에 읽기 전용 list_agent_sessions와 get_agent_session이 추가됐습니다. 세션 목록을 상태·출처·날짜로 걸러 보고, 특정 세션의 사용자 입력·모델 응답·도구 입출력·오류·토큰 사용량을 텍스트 transcript로 조회할 수 있습니다. call_agent 결과의 sessionId로 자기 테스트 기록을 연결하고, 선택적 executionId로 특정 턴과 이어진 재개 턴을 좁혀 볼 수 있습니다.

사용 전 Agent 모듈과 접근 설정을 확인해야 합니다. 버전 이력 PR의 검증 조건에는 N8N_ENABLED_MODULES=agents가 명시돼 있고, 세션 로그 도구는 설정에서 MCP 접근 및 대상 Agent의 MCP 접근을 활성화한 뒤 사용하는 흐름입니다. 이 확인을 모든 플랜·설치에서 기본 활성화됐다는 뜻으로 해석하지 않습니다.

살펴볼 점
  • 세션 로그 transcript는 길이를 제한합니다. 긴 텍스트·도구 값이 잘리거나 매우 긴 세션의 오래된 턴이 제외될 수 있고, raw tool call ID나 nodeParameters 전체는 포함되지 않습니다. 전체 실행 데이터 보관이나 완전한 감사 로그의 대체물로 보지 마세요.
  • 로그에는 입력과 도구 입출력이 들어갈 수 있으므로 MCP 연결 대상과 접근권한을 검토하세요. 읽기 전용 로그 도구와 Agent 실행 도구의 권한·부작용은 별개입니다.
  • 이번 확인은 릴리스·연결 PR 원문 검토입니다. 설치·업그레이드·MCP 연결·Agent 실행을 하지 않았고 플랜별 제공 범위·모델 호출 비용·운영 안정성을 실측하지 않았습니다. 기존 메모리 recall·통합 개선도 있지만 메모리 기능 전체가 이번에 처음 출시됐다고 소개하지 않습니다.
  • 이 카드는 업데이트 기능 소개다. n8n 전체를 무제한 무료 상업 서비스로 소개하지 않으며 자체 호스팅·서비스 제공·재판매의 라이선스 조건은 별도로 확인한다. 이번에 라이선스 전문을 추가 검토한 것은 아니다.
