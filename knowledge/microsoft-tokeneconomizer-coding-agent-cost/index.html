TokenEconomizer: 반복 저장소 작업 경험으로 코딩 에이전트 비용 줄이기

UC버클리·Microsoft Research 공동 연구로, 반복 작업한 저장소에서의 경험을 학습해 마이크로스킬 주입·미사용 도구 정리·반복 실패 개입으로 코딩 에이전트 비용을 줄이는 플러그인

#Claude Code#Codex#비용 관리#Microsoft Research

무엇을 할 수 있나요?

공식 논문·README: Claude Code, Codex, GitHub Copilot CLI, Pi용 플러그인이며 opencode는 실험 지원입니다. 6개 저장소의 동일한 SWE-Bench 277개 작업을 5개 에이전트-모델 조합으로 평가해, 조합별 평균 비용 18.4~30.9% 감소와 총 30개 저장소×조합 칸 모두의 비용 감소를 보고했습니다. 30개 저장소를 평가한 뜻은 아니며, Pass@1은 5개 조합 중 4개에서 높아졌다고 합니다. 지원 호스트·버전 범위와 opencode의 제한된 테스트 버전은 설치 문서에서 확인해야 합니다.

세 가지 메커니즘: (1) 마이크로스킬 - 반복되는 빌드 명령·환경변수 등 저장소별 사실을 3회 이상 세션에서 확인되면 다음 세션 시작 시 주입하고, 이후 세션이 반박하면 제거합니다. (2) 도구 가지치기 - 일정 기간 쓰이지 않은 도구 정의를 다음 세션 설정에서 빼서 매 요청마다 전송되는 도구 목록 토큰을 줄입니다(설정으로 복원 가능). (3) 실패 루프 개입 - 같은 실패를 반복하는 턴을 판정 모델이 감지하면 다른 접근을 시도하도록 짧은 안내를 주입(턴당 최대 1회), 그래도 막히면 직접 멈추지 않고 사용자에게 멈추는 법을 안내합니다.

학습 상태는 로컬 ~/.tokeneconomizer에 저장되지만 사실 제안자·판정 모델 호출은 사용자가 설정한 에이전트의 같은 로그인·요금제를 통해 수행되며 비용 보고에도 포함됩니다. 로컬 저장이 호출 과정의 코드·로그 등 데이터가 외부 모델 공급자에게 전송되지 않는다는 뜻은 아닙니다. 실제 호출 경로와 데이터 정책은 사용하는 에이전트·공급자 설정에 따라 확인해야 합니다.

살펴볼 점
  • 수치는 연구팀이 자체 SWE-Bench/Web-Bench 환경에서 측정한 결과이며, 모든 저장소·작업에서 동일한 절감률을 보장하지 않습니다.
  • 설치 시 호스트별 폴더·훅 신뢰 확인이 필요할 수 있고, 도구 가지치기는 호스트 설정을 바꿔 도구를 제외합니다. 도구가 안 보이면 해당 호스트의 문서화된 toolprune restore로 플러그인이 추가한 제외 항목을 복원할 수 있습니다. 오류 시 세션은 계속 진행하도록 설계됐다고 설명하지만 직접 설치·검증한 것은 아닙니다.
  • Apache 2.0 라이선스로 공개돼 있으나 실제 저장소에 적용했을 때의 체감 절감폭은 사용 패턴에 따라 달라질 수 있습니다.
