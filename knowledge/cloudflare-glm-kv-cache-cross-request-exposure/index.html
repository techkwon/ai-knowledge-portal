Cloudflare Workers AI GLM 5.3 KV 캐시 교차 노출 사고 전문 공개

긴 프롬프트가 거부 처리되는 과정의 버그로 다른 사용자의 이전 요청 데이터가 응답에 섞여 나온 사고의 원인·대응·교훈을 Cloudflare가 전문 공개한 보안 사고 보고서

#LLM 추론 엔진#KV 캐시#SGLang#사고 대응

무엇을 할 수 있나요?

사고 내용: Cloudflare는 2026년 8월 27일~9월 9일 GLM 5.3 모델에서 681,280토큰보다 긴 프롬프트에 대한 응답 155건에 다른 고객의 이전 요청 데이터가 섞였다고 보고했다. HackerOne 제보 접수는 9월 8일 23:11 UTC, 사고 선언은 9월 9일 13:22 UTC, 모델 비공개 전환은 같은 날 14:00 UTC였다. 약 40분은 제보 접수부터가 아니라 사고 선언부터 차단까지의 시간이다. 수정 후 9월 9일 서비스를 복구했으며 고의적 악용의 증거는 찾지 못했다고 밝혔다.

근본 원인: GLM 5.3의 컨텍스트 창(1,048,576토큰)이 실제 GPU의 KV 캐시 풀 용량(681,280토큰)보다 크게 설정되어 있었고, 이 한도를 넘는 요청은 내부적으로 "거부(reject)"로 표시되고 1토큰짜리 더미 프롬프트로 치환됐다. 그런데 분산(prefill/decode 분리) 구성에서 "거부됨" 상태가 "완료됨" 상태와 구분되지 않아, 거부된 요청이 정상 요청처럼 decode 노드로 전달되면서 이전 요청이 남겨둔 캐시 페이지를 그대로 읽어버렸다.

조치: (1) 해당 GLM 5.3 배포의 KV 풀이 전체 컨텍스트를 수용하도록 설정 수정, (2) 거부된 요청을 분산 전달 전에 종료하는 엔진 패치 적용 및 SGLang 상류 협업, (3) 캐시 수명·지연 해제·전송 안전장치 보강. 사고 경로를 막는 #36988은 v0.5.20, 조기 거부 #38935는 v0.5.21에 포함됐고, 후속 보완까지 포함하는 v0.5.22 이상으로 업그레이드를 권고한다.

다른 운영자를 위한 권고 요약: 분산 prefill/decode 모드에서는 배포 변경마다 양쪽 노드의 실제 KV 풀과 컨텍스트 길이를 대조하고, v0.5.22 이상 또는 관련 패치를 포함한 빌드로 업데이트한다. 양쪽 역할에서 지연 KV 해제를 사용하며 Mooncake 전송 배치를 제한하고, 프록시가 첫 토큰 전에 불필요한 중단을 만들지 않도록 설정한다. 체크섬·KV canary는 지원되는 모델에서만 켜고 검증 로그를 확인한다. 보고서 당시 GLM 5.3 등을 포함한 일부 아키텍처로 지원을 확장하는 작업은 진행 중이었다.

살펴볼 점
  • 영향받은 모델은 GLM 5.3 하나뿐이며, Workers AI의 다른 모델은 이 문제의 전제 조건(컨텍스트보다 작은 KV 풀)에 해당하지 않아 영향받지 않았다고 공식 글은 밝힌다.
  • 이 카드는 Cloudflare/SGLang 생태계에서 자체 인프라(특히 분산 prefill/decode 구성)를 운영하는 개발자에게 유용한 내용이며, 일반 API 사용자가 직접 설정을 바꿀 수 있는 부분은 아니다.
  • 수치(155건, 681,280토큰 등)는 공식 보고서의 주장이며 독립 검증 결과가 아니다.
