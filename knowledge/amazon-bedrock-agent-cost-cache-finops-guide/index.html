Amazon Bedrock 에이전트 비용 운영: 캐시·청구 귀속·예산 통제 연결하기

캐시 할인만 보지 않고 누가 썼는지, 실제로 재사용됐는지, 예산 초과를 막는지까지 점검하는 AWS 공식 운영 가이드. Runtime과 Mantle의 비용 귀속·로그 차이를 구분합니다.

#Amazon Bedrock#AWS#FinOps#프롬프트 캐싱#비용 귀속#CloudWatch

무엇을 할 수 있나요?

운영 순서는 비용 귀속→요청 관측→예산 통제→최적화→정기 검토입니다. 단가가 낮은 모델을 고르거나 프롬프트를 줄이기 전에 사용자·팀·앱별 비용을 구분하고, 성공한 작업 한 건의 비용으로 평가합니다. 청구서는 CUR 2.0·Cost Explorer에서, 요청별 토큰과 원인은 로그에서 확인해 대조하는 방식입니다.

엔드포인트를 먼저 구분합니다. Runtime은 IAM principal·세션 태그로 사용자/팀 비용을 귀속하고 application inference profile로 앱별 비용을 구분할 수 있습니다. Mantle의 Responses·Chat Completions는 Projects로 앱·작업 비용을 구분합니다. Project는 여러 모델을 포괄하지만 비용의 최소 집계 단위는 usage type별 하루이며, 요청별 비용이나 요청 metadata tagging을 제공하지 않습니다. 비용 태그는 활성화 전 지출에 소급 적용되지 않습니다.

Runtime의 model invocation logging은 기본 꺼짐이며, 지원되는 Responses·Chat Completions 호출도 기록할 수 있습니다. Mantle 호출은 이 로그에 포함되지 않습니다. 캐시 관측도 Runtime은 CloudWatch의 CacheReadInputTokenCount·CacheWriteInputTokenCount를, Mantle은 응답 usage의 cached_tokens·cache_write_tokens를 앱에서 기록하는 방식으로 구분합니다.

AWS 명시적 캐시 지원 표에는 openai.gpt-5.6-sol/terra/luna, openai.gpt-6-astra/sol/luna, openai.gpt-6.1-sol이 기재돼 있습니다. 접두부 최소 1,024토큰, 요청당 최대 4회 캐시 쓰기, TTL 옵션은 30m만 지원합니다. 최근 쓰기·성공적 재사용 뒤 최소 30분 유지되며 더 오래 남을 수 있습니다. 실제 모델 가용 리전과 엔드포인트는 별도 확인해야 하며, 블로그의 us.openai.gpt-6-astra 예제를 모든 리전에 그대로 쓰면 안 됩니다. 해당 GPT 모델의 Converse 명시적 캐싱은 지원하지 않습니다.

공유 도구·지침 뒤에 명시적 중단점을 두고 변화하는 대화는 뒤에 덧붙입니다. implicit 모드는 자동 중단점과 명시적 중단점을 함께 쓸 수 있고, explicit 모드는 표시한 지점만 사용합니다. 세션 간 재사용에는 같은 모델·AWS 계정·리전과 일치하는 접두부가 필요하며, 공유할 요청은 같은 prompt_cache_key를 사용합니다. store=False는 응답 저장 설정이지 캐시 비활성화 설정이 아닙니다.

GPT-5.6 이후 해당 모델의 캐시 쓰기 토큰은 일반 입력 단가의 1.25배, 읽기는 모델별 할인 단가, 나머지 입력은 일반 단가로 구분합니다. 1.25배는 쓰기 토큰의 적용 단가이지 일반 입력에 추가로 1.25배를 더하는 뜻이 아닙니다. 출력 토큰은 별도 비용입니다. 읽기·쓰기·일반 입력 비용을 나누고 출력 비용까지 합쳐 평가해야 하며, 미리 캐시를 준비하는 요청도 무료라고 가정하지 않습니다.

Budgets 경보는 초과 지출을 자동 차단하지 않습니다. IAM 정책·자격증명 발급 통제는 비동기라 반영 지연이 있고, 요청 경로의 게이트웨이는 동기식 한도 차단을 설계할 수 있지만 운영·보안 검토가 추가됩니다. 캐시 읽기/쓰기 비율, 오류·재시도, 저비용 모델 비중, metadata 누락률을 함께 점검합니다.

살펴볼 점
  • 30분 TTL, 명시적 중단점, 접두부 고정, 1.25배 쓰기는 OpenAI 직접 API에도 있는 내용입니다. 이 카드의 추가 가치는 AWS 비용 귀속·관측·통제에 있으며 캐싱의 새 발명으로 소개하지 않습니다. 직접 OpenAI API의 12h 옵션이나 Claude의 5분·1시간 요금을 AWS OpenAI 모델에 옮겨 적용하지 마세요.
  • 캐시 키를 인증·권한 분리의 대체 수단으로 가정하지 마세요. model invocation logging에는 입력·출력과 도구 결과의 민감정보가 남을 수 있으므로 접근권한·암호화·보존정책을 검토해야 합니다. 요청 metadata·세션 태그에는 개인정보, 인증정보, 비밀을 넣지 않습니다.
  • 특정 워크로드의 62~64% 입력 비용 절감은 전체 서비스 비용 절감 보장이 아닙니다. 모델·리전별 실제 읽기/출력 단가, 로깅·저장·게이트웨이 등 관련 서비스 비용을 별도로 확인해야 합니다. 이번 확인에서는 동적 요금표와 모델별 리전 표의 값이 추출되지 않아 금액·지원 리전을 확정하지 않았습니다.
  • 공식 문서 확인만 했습니다. AWS 가입·계정 설정·실제 모델 호출·캐시 적중·청구액 측정은 하지 않았습니다.
