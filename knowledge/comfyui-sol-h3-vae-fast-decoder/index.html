Sol-H3-VAE: ComfyUI용 MiniMax H3 고속 VAE 디코더

24레이어 증류 H3 VAE 디코더의 ComfyUI 지원 변경. PR 작성자는 RTX 5090 예제에서 동일 정밀도끼리 FP16 약 3.3배·INT8 약 2.7배 빠른 디코딩을 보고했으며 master 병합을 확인

#ComfyUI#MiniMax H3#VAE#추론 가속

무엇을 할 수 있나요?

공식 PR 설명: Sol-H3-VAE(Hugging Face: Efficient-Large-Model/Sol-H3-VAE)는 H3 VAE 디코더를 24개 레이어로 증류한 디코더로, 256px 타일과 겹치는 시간 청크 방식 대신 16x16 토큰 공간 윈도우와 5-latent 시간 윈도우로 클립 전체를 한 번에 디코드합니다. 디코더만 있는 파일을 그대로 쓰거나 H3 인코더와 합쳐 하나의 VAE 파일로 쓸 수 있습니다.

PR 작성자의 RTX 5090·1344×768·124프레임 측정: H3 VAE FP16 10.7초→Sol FP16 3.28초(약 3.3배), H3 VAE INT8 4.61초→Sol INT8 1.70초(약 2.7배). 약 6.3배는 기존 FP16과 Sol INT8을 비교한 서로 다른 정밀도 조합입니다. 같은 예제의 피크 VRAM은 FP16 5.5→5.9GiB, INT8 3.2→4.3GiB로 늘었고, 활성화 메모리는 클립 길이와 해상도에 따라 커집니다. 타일링을 지원하지 않아 VAEDecodeTiled도 클립 전체를 디코드합니다.

품질: 증류된 디코더라 완전히 무손실은 아니며, 생성된 768p 클립 기준 원본 디코더 대비 39dB PSNR(NVIDIA 보고 38.2dB)로 시각적으로는 거의 동일하지만 미세 텍스처에서 차이가 있다고 PR 설명이 명시합니다.

살펴볼 점
  • GitHub PR #17411은 ComfyUI master에 병합된 상태를 직접 확인했습니다. 특정 안정 릴리스·사용자 설치본에 포함됐는지는 별도 확인이 필요하며, 속도·화질 수치는 작성자 측정이지 이 사이트의 직접 검증이 아닙니다.
  • 타일링을 지원하지 않아 긴 클립일수록 VRAM 활성화 메모리가 커지므로, 저사양 GPU에서는 오히려 메모리 부족 위험이 있습니다.
  • 직접 설치·디코딩 테스트는 하지 않았으며 PR 본문 확인에 한정합니다.
