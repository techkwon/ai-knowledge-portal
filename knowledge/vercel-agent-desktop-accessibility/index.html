agent-desktop: 접근성 트리로 데스크톱 앱을 다루는 에이전트 도구

macOS·Windows·Linux 앱의 접근성 트리를 JSON으로 읽고 요소 참조로 조작하는 CLI·C 라이브러리·MCP 도구. 권한과 OS별 입력 제약을 먼저 확인해야 한다.

#agent-desktop#Vercel Labs#접근성#데스크톱 자동화#MCP#오픈소스

무엇을 할 수 있나요?

공식 README에 따르면 스크린샷의 픽셀 매칭 대신 OS 접근성 트리를 JSON과 요소 참조로 제공한다. 클릭·입력 뒤 다시 관찰하는 판단 루프와 AI 모델은 호출 에이전트가 담당한다.

CLI와 C 라이브러리를 제공하고, stdio MCP 서버는 CLI 명령을 desktop_ 접두사 도구로 노출한다. 기본 참조 동작은 포인터나 포커스를 바꾸지 않는 의미 기반 방식이며 물리 입력은 OS와 명령에 따라 별도 모드가 필요하다.

문서상 지원 기준은 macOS 13 이상, Windows 10 1809 이상 또는 Server 2019 이상, Ubuntu 24.04 이상이다. Intel/x64와 Apple Silicon/ARM64 계열을 지원하지만 OS별 실행 파일과 헬퍼를 사용해야 한다.

npm 설치 방식은 Node 18 이상이 필요하다. 네이티브 아카이브로는 JavaScript 런처 없이 사용할 수 있으며 Linux는 AT-SPI와 사용자 그래픽 세션 등 추가 환경 조건이 있다.

실제 LICENSE는 Apache-2.0이다. 재배포·수정에는 라이선스 사본, 변경 고지, 관련 저작권·귀속 고지와 해당 NOTICE 유지 등의 조건이 적용된다.

UI가 바뀌면 새 관찰을 요구하며 오래되거나 모호한 참조는 거절하도록 문서화되어 있다. 이는 설계 설명이며 실제 앱에서의 성공률이나 속도를 확인한 결과는 아니다.

살펴볼 점
  • macOS는 실행 호스트의 접근성 권한이 필요하다. 화면 캡처는 화면 기록, 일부 시스템 동작은 자동화 권한도 요구한다.
  • Windows는 로그인한 사용자의 대화형 데스크톱이 필요하고 잠금 화면·UAC 보안 화면·서비스 세션은 지원하지 않는다. 바이너리 미서명에 따른 보안 경고·차단 가능성도 공식 문서에 명시되어 있다.
  • Linux의 X11과 Wayland 지원은 동일하지 않다. Wayland의 포인터 제스처·창 제어, Electron 네이티브 대화상자 등에는 제약이 있고 접근성을 노출하지 않는 UI는 읽거나 조작하지 못할 수 있다.
  • MCP는 접근 가능한 앱 전체와 프로그램 실행까지 다룰 수 있다. 삭제·전송·구매 같은 중요 작업은 클라이언트의 승인 절차를 유지하고 화면에서 읽은 지시문은 신뢰하지 않는다.
  • 스냅샷·클립보드·알림·캡처·디버그 파일과 호출 에이전트의 대화 기록에는 개인정보가 들어갈 수 있다. 추적 텍스트 일부가 가려져도 스크린샷과 HTML은 가려지지 않으므로 공개 업로드하지 않는다.
  • 로컬 도구에 모델이 없다는 설명은 연결한 외부 AI로 데이터가 전혀 전송되지 않는다는 보장이 아니다. 클라이언트의 전송 범위·보관 정책·모델 요금은 별도로 확인해야 한다.
  • 기능별 자원 제한이 있으며 MCP는 동시 호출 8개와 메시지 4 MiB 한도를 둔다. 접근성 동작의 성공 반환만으로 실제 결과를 보장하지 않으므로 화면 상태를 다시 확인해야 한다.
  • 검토한 문서에서 베타라는 표시는 확인하지 못했지만 모든 앱·OS에서 완전 동작을 보장하는 뜻은 아니다. 설치·CLI 실행·권한 부여·MCP 연결·성능 측정은 하지 않았다.
