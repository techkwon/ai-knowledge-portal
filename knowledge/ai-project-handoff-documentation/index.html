AI로 만든 프로젝트의 인수인계 문서 나누기

사람이 판단할 운영 문서와 에이전트가 실행할 작업 지침을 구분해 유지보수 공백을 줄이는 방법

#커뮤니티 인사이트#실무 가이드

무엇을 할 수 있나요?

핵심 원리: 코드를 공개하는 것과 운영 책임을 넘기는 것은 다릅니다. GitHub README 권고 항목인 목적·시작 방법·도움받는 곳·관리 주체를 바탕으로 아래 문서 구성을 제안합니다.

사람용 README에는 서비스 목적, 사용자, 담당 역할, 주요 설계 결정과 근거, 데이터 흐름, 장애 시 중단·복구 절차를 씁니다. 계정 비밀번호 대신 권한 요청 절차를 적습니다.

에이전트용 작업 지침에는 설치·테스트·빌드 명령, 수정 허용 범위, 금지 작업, 변경 후 검증 기준을 기록합니다. README에서 해당 파일을 연결하고 중복 설명은 한 곳을 기준 문서로 정합니다.

예시 점검: 다른 사람이 깨끗한 환경에서 문서만 보고 실행·테스트하고 실패한 단계를 남기게 합니다. AI에는 “실제 파일과 문서를 비교해 불일치만 보고하고 배포는 하지 마”라고 요청할 수 있습니다.

적용 조건: 개인 프로젝트를 팀으로 넘기거나 장기간 유지할 때 유용합니다. 인계받을 사람과 권한·백업·유지보수 범위를 합의하고 변경 때마다 문서를 갱신합니다.
