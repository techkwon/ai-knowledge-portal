MiniMax M3.1 Flash GGUF: 활성 23B와 Q2의 160GiB급 메모리 권고

코딩·에이전트 작업용 멀티모달 MoE 모델의 Unsloth GGUF 배포 자료. 총 428B 중 토큰당 23B가 활성화되지만 전체 양자화 가중치 크기를 기준으로 메모리를 계획해야 한다. 16K 텍스트·동시 슬롯 1개에서 Q2는 RAM+VRAM 또는 통합메모리 160GiB 이상을 계획하는 고메모리 선택지다.

#MiniMax#M3.1 Flash#GGUF#Unsloth#로컬 AI#MoE#멀티모달#라이선스

무엇을 할 수 있나요?

무엇을 위한 모델인가: MiniMax 공식 모델 카드는 코딩, 에이전트 워크플로, 컴퓨터 사용, 사이버보안 용도로 소개한다. 텍스트·이미지·영상을 입력하고 텍스트를 출력한다. 영상 생성 모델 H3와는 다른 모델이다.

총량과 활성량: 개발사 설명은 약 428B 전체 파라미터와 토큰당 23B 활성 파라미터다. 23B는 계산에 참여하는 부분의 규모이지 전체 가중치를 23B만 보관하면 된다는 뜻이 아니다. Hugging Face 자동 집계의 220B 또는 426B 표시를 공식 아키텍처 총량과 혼용하지 않는다.

실제 다운로드 크기: Hugging Face 샤드 메타데이터 합산으로 IQ1_M은 4개 파일 총 129.361GB, 약 120.477GiB다. Q2_K_XL은 4개 총 143.910GB, 약 134.027GiB이며 Q4_K_XL은 7개 총 249.402GB, 약 232.274GiB다. 이는 가중치 크기일 뿐 실행 메모리가 아니다. 첫 8.24MB 샤드만으로 실행하는 작은 모델이 아니다.

하드웨어 계획: Unsloth 본문은 16K 텍스트 컨텍스트와 동시 슬롯 1개에서 Q2_K_XL에 RAM+VRAM 합계 또는 통합메모리 160GiB 이상, Q4_K_XL에 256GiB 이상을 출발점으로 권고한다. 문서가 GB라고 쓰는 메모리 목표는 설명상 GiB다. 이는 엄격한 최저 사양이나 실행 성공 보장이 아니며 가중치 외 KV cache, 런타임, OS 여유가 필요하다.

VRAM과 offload: 위 수치는 단일 GPU의 최소 VRAM이 아니라 호스트 RAM과 GPU VRAM을 나누어 쓰는 경우 또는 통합메모리의 계획치다. GPU 메모리가 부족하면 CPU offload가 가능하다고 안내하지만 전체 가중치는 RAM·VRAM에 담도록 계획해야 한다. GPU에 모두 상주시키려면 선택한 가중치와 실행 여유를 VRAM에 수용해야 하며 GPU별 최소 구성이나 속도는 여기서 검증하지 않았다. 일반 8~32GB PC에서 가볍게 돌리는 모델로 소개할 수 없다.

컨텍스트와 부가 기능: 최대 1M 토큰은 모델 지원 상한이다. 위 160GiB·256GiB 계획으로 1M 컨텍스트가 보장되지 않는다. 긴 컨텍스트, 여러 슬롯, 이미지·영상 처리에는 추가 메모리가 든다. 이미지 입력용 BF16 projector는 별도 약 1.74GB이며 DSpark draft는 별도 약 2.09GB와 추가 실행 메모리 및 호환 런타임을 요구한다.

성능 자료의 범위: 개발사는 공식 가중치에 DeepSWE v1.1 73.7과 OSWorld 2.0 61.7 등을 보고했다. DeepSWE는 mini-SWE-agent 2.4.5, 512K 컨텍스트 조건이다. 이 수치는 직접 추론한 결과나 해당 GGUF의 성능 보장이 아니다. Unsloth의 top-1 token agreement는 기준 출력과의 일치도이지 일반 정답률이나 업무 성공률이 아니다.

기반 모델 라이선스: 실제 M3.1 Flash LICENSE는 MINIMAX COMMUNITY LICENSE다. 비상업 이용을 허용하되 저작권·허가문 보존 및 금지 용도를 준수해야 한다. 상업 이용은 Built with MiniMax M3.1-Flash 표시가 필요하고, 관련 제품·서비스 연매출 2천만 달러 초과 시 MiniMax의 사전 서면 승인이 필요하다. 그 이하는 공식 LICENSE에 기재된 주소로 1회 통지가 필요하므로 무조건 자유로운 상업 이용으로 표시하지 않는다.

지역과 파생 GGUF를 구분: 읽은 M3.1 Flash LICENSE 전문에는 대한민국 제외나 Excluded Territories 조항이 없다. H3 영상 모델의 지역 제한을 여기에 옮겨 적용하지 않는다. 다만 적용 법률·규정 준수 의무는 있고, API 서비스의 별도 지역 정책까지 확인한 것은 아니다. Unsloth GGUF는 기반 모델과 minimax-community 라이선스를 선언하지만 상대 LICENSE 링크는 404였다. 독립된 GGUF 라이선스 전문이 확인된 것처럼 쓰지 않으며, 기반 모델의 파생물 조항과 상업 이용 의무가 양자화로 사라지지 않는다고 안내한다.

살펴볼 점
  • 문서·라이선스·파일 목록만 확인했다. 설치, 추론, 속도·한국어 품질 평가, 가중치 다운로드는 하지 않았다.
  • Unsloth 문서 내부의 메모리 요약표와 본문은 불일치한다. Q2 표의 150보다 본문의 160GiB 이상 권고를 채택했다. IQ1의 134라는 요약 수치를 검증된 최저 메모리로 재인용하지 않는다.
  • RAM+VRAM 합계는 모든 조합의 동일 속도나 실행 보장을 의미하지 않는다. CPU offload의 실제 속도와 최적 GPU 구성은 미검증이다.
  • GGUF 저장소에 별도 LICENSE 파일이 없어 상업 서비스 배포 전에는 원개발사 실제 원문과 배포자의 라이선스 안내를 다시 확인해야 한다. 일반 MIT·Apache 라이선스 모델로 표기하지 않는다.
  • 실제 LICENSE 원시 파일에는 2천만 달러 이하 상업 이용자의 1회 통지 의무가 있다. blob 페이지의 추출 결과만 보고 이를 누락하지 않는다.
  • 법률 자문이 아니며 H3 라이선스, MiniMax API 서비스 약관, M3.1 가중치 라이선스는 서로 구분해야 한다.
