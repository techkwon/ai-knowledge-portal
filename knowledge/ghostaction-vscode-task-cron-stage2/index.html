GhostAction Stage 2: 가짜 폰트 파일로 VS Code에 크론 작업 심는 공급망 공격

탈취한 GitHub 권한으로 심어둔 보안 감사 워크플로(1단계)를 사용자가 지워도, VS Code가 자동 실행하는 작업 정의와 가짜 폰트 파일(2단계)이 남아 지속적으로 정보를 탈취하는 공급망 공격 수법과 대응 교훈

#공급망 공격#GitHub Actions#VS Code#자격증명 탈취

무엇을 할 수 있나요?

기존(1단계): 탈취한 GitHub 계정 권한으로 접근 가능한 모든 저장소에 "security audit"라는 이름의 악성 워크플로를 밀어넣어, 저장소의 비밀 값과 git 기록에 남은 자격증명을 공격자 서버로 전송한다.

신규 발견(2단계): 저장소에 `.vscode/tasks.json`(폴더를 열면 자동 실행되도록 설정되고 UI에서 숨겨짐)과 `public/fonts/fa-solid-400.woff2`라는 이름의 가짜 폰트 파일(실제로는 실행 코드)을 함께 심는다. 이 작업은 VS Code에서 폴더를 여는 즉시 실행되며, 1단계 워크플로를 지워도 사라지지 않고 5분마다 공격자 서버의 명령을 실행하는 크론 작업을 설치해 지속한다.

규모: 2026-10-26 기준 1,230개 저장소(391개 계정)에서 2단계 감염이 확인됐고, 그중 114개는 1단계 워크플로 없이도 2단계만 심어져 있어 "워크플로만 지우면 안전하다"는 가정이 틀렸음을 보여준다.

대응 교훈(일반화 가능): 악성 GitHub Actions 워크플로를 발견했을 때는 워크플로 파일 삭제만으로 끝내지 말고, (1) 노출된 토큰·자격증명을 즉시 폐기하고, (2) `.vscode/tasks.json`처럼 폴더를 열면 자동 실행되는 설정 파일이 남아있는지 점검하고, (3) 리포지토리에 낯선 바이너리/폰트 파일이 있는지 확인해야 한다.

살펴볼 점
  • 이 분석은 보안 연구 조직(opensourcemalware.com, Jamf Threat Labs와 협업)의 자체 조사 결과이며, 국가 행위자 귀속(북한 연계 등)은 조사 기관의 판단이지 독립적으로 재검증한 것은 아니다.
  • 특정 리포지토리·계정을 공개 식별하지 않았으며, 이 카드는 공격 기법과 대응 교훈만 요약한 것이다.
  • 탐지 규칙이나 방어 도구를 직접 설치·검증한 것은 아니다.
