GhostAction Stage 2: VS Code 자동작업과 가짜 폰트 파일을 이용한 지속성 공격

악성 GitHub Actions 워크플로를 지워도 VS Code 작업 정의·가짜 폰트 파일·운영체제 예약 작업이 남을 수 있다는 공급망 공격 조사. 자동실행에는 신뢰된 작업공간과 허용 설정이 필요

#공급망 공격#GitHub Actions#VS Code#자격증명 탈취

무엇을 할 수 있나요?

기존(1단계): 탈취한 GitHub 계정 권한으로 접근 가능한 모든 저장소에 "security audit"라는 이름의 악성 워크플로를 밀어넣어, 저장소의 비밀 값과 git 기록에 남은 자격증명을 공격자 서버로 전송한다.

신규 발견(2단계): `.vscode/tasks.json`의 `runOn: folderOpen` 작업이 폰트로 위장한 실행 코드 `public/fonts/fa-solid-400.woff2`를 실행한다. VS Code에서 폴더를 여는 것만으로 항상 실행되는 것은 아니며, 신뢰된 작업공간에서 자동작업 실행이 허용되어야 한다. 실행되면 자격증명을 탈취하고 macOS/Linux에서는 5분마다 원격 명령을 가져오는 크론 작업을 설치한다. Windows에서도 탈취 코드는 실행될 수 있지만 crontab이 없어 같은 크론 지속성은 설치되지 않는다고 원문은 설명한다.

규모: 2026-10-26 기준 1,230개 저장소(391개 계정)에서 2단계 감염이 확인됐고, 그중 114개는 1단계 워크플로 없이도 2단계만 심어져 있어 "워크플로만 지우면 안전하다"는 가정이 틀렸음을 보여준다.

대응 교훈: 워크플로 파일 삭제만으로 끝내지 말고, 자동작업을 차단한 뒤 모든 브랜치의 악성 워크플로·작업 정의·가짜 폰트와 기기의 크론 등 지속성을 함께 점검해야 한다. 실행 흔적이 있다면 기기를 격리하고 추가 감염·재설치 필요성을 평가한 뒤, 깨끗한 기기에서 노출 자격증명을 폐기·교체한다. 악성 코드가 계속 실행 중인 기기에서 토큰만 바꾸는 것으로는 충분하지 않다.

살펴볼 점
  • OpenSourceMalware의 조사 보고이며 Jamf Threat Labs 연구자의 발견을 바탕으로 한다. 원문은 GhostAction을 북한 연계 PolinRider 기법의 모방 사례로 분류하며 두 캠페인의 직접 연계는 확인하지 않았다고 명시한다. GhostAction 자체를 북한 소행으로 단정하지 말 것.
  • 특정 리포지토리·계정을 공개 식별하지 않았으며, 이 카드는 공격 기법과 대응 교훈만 요약한 것이다.
  • 탐지 규칙이나 방어 도구를 직접 설치·검증한 것은 아니다.
