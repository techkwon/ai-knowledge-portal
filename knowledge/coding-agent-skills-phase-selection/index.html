코딩 스킬 선택 가이드: 요구사항·구현·검증을 나눠 고르기

스킬 묶음의 홍보 문구보다 필요한 단계와 실제 증거·중단 조건을 기준으로 코딩 에이전트 워크플로를 선택하는 방법

#스킬#TDD#검수

무엇을 할 수 있나요?

요구사항 단계에서는 질문·공통 용어·명세를, 구현에서는 작은 변경과 실패 재현 테스트를, 검증에서는 실행 결과·리뷰·회귀 테스트를 따로 확인하세요. 한 도구가 모든 단계를 자동 해결한다는 가정부터 피하는 방식입니다.

Matt Pocock의 공식 저장소는 grill-with-docs·tdd·diagnosing-bugs 등을, Addy Osmani의 저장소는 spec·plan·build·test·review 흐름을 안내합니다. pstack은 setup과 poteto-mode 및 harness별 제약을 설명합니다. 이는 저장소의 구성이지 세 도구의 객관적 품질 순위가 아닙니다.

설치 전 지원 harness·명령 이름·참조 파일 위치·자동 적용 범위를 확인하고 한 단계씩 시도하세요. 예컨대 Addy 저장소는 개별 스킬 복사 시 공통 references가 함께 설치되지 않을 수 있는 제약을 명시합니다.

살펴볼 점
  • 스킬의 이름·명령·모델 기본값은 바뀔 수 있습니다. 실제 설치판 문서와 diff·테스트 로그를 확인하고 같은 스킬의 중복 설치를 피하세요.
  • 계획 승인·구현·테스트 통과·배포 승인을 서로 다른 상태로 관리하세요. 스킬 설치가 정확한 결과나 안전한 자동 배포를 보장하지는 않습니다.
  • 공식 문서 확인 기준이며 설치·실행·성능을 직접 시험하지 않았습니다.
