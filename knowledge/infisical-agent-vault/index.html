Infisical Agent Vault: 실제 자격증명을 에이전트와 분리하는 프록시

API·MCP 호출에 실제 키를 대신 붙이는 프록시와 제한된 세션을 결합한다. 키 비노출만으로 안전이 보장되지는 않으며 환경 격리·최소 권한·세션 회수가 함께 필요하다.

#Infisical#자격증명#최소 권한#MCP

무엇을 할 수 있나요?

Agent Vault는 HTTP API와 MCP 서버에 접근할 때 에이전트 대신 프록시가 실제 API 키·토큰·OAuth 자격증명을 첨부하는 구조다. 에이전트는 실제 키 대신 하나의 access bundle에 한정된 세션 토큰을 받는다.

구성 순서는 프로젝트 생성, 서비스와 허용 호스트·HTTP 메서드·경로 정의, access bundle 구성, 실행별 세션 생성, 별도 환경의 프록시를 통한 호출이다. 수명이 없는 세션도 가능하므로 작업에 필요한 짧은 만료 시간을 정하고 종료 시 회수하는 편이 낫다.

오케스트레이터는 세션 생성 권한을, 프록시는 proxy token을 가진다. 이를 에이전트와 같은 파일·환경에 두지 않고 컨테이너·VM 등으로 분리하고 네트워크도 프록시를 우회하지 못하도록 설계한다.

HTTPS_PROXY를 읽는 클라이언트에 적용되며 프록시 CA 신뢰 설정을 사용한다. 공식 문서는 Node의 내장 fetch는 기본적으로 이 환경변수를 따르지 않는다고 주의하고 Node 24 이상에서는 --use-env-proxy 또는 NODE_USE_ENV_PROXY=1을 안내한다.

살펴볼 점
  • 문서 확인만 했으며 설치·키 등록·트래픽 차단·토큰 유출 시험은 하지 않았다. 실제 프록시 통과 여부와 차단 정책은 사용 환경에서 검증해야 한다.
  • 세션 토큰도 권한을 가진 비밀정보다. 유출 시 만료·회수 전까지 허용 범위의 작업이 가능하며, 실제 키를 숨겨도 허용된 API의 오용까지 없애지는 못한다.
  • 공식 문서는 에이전트와 프록시 사이 세션 토큰이 평문 HTTP로 전달된다고 설명한다. 공용 인터넷에 그대로 노출하지 말고 전용 사설망 또는 작업별 격리 프록시 구성을 검토한다.
  • 구독 로그인이나 기존 API 권한을 자동으로 제공하는 도구가 아니다. 필요한 서비스 자격증명·OAuth 권한과 현재 요금·배포 조건은 별도로 확인한다.
