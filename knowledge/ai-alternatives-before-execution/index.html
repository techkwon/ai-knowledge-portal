활용법자료 확인

AI에게 대안과 작업 방법을 제안받는 질문법

해결책을 먼저 고정하지 않고 목표·제약·평가 기준을 제시해 대안을 비교한 뒤 작은 실험으로 검증하는 질문 설계

#커뮤니티 인사이트#실무 가이드

무엇을 할 수 있나요?

핵심 원리: 목적과 맥락은 명확히 주되 구현 방법은 여러 후보로 제안받습니다. 다음 절차는 공식 문서의 목표·맥락·예시·평가 원칙을 조합한 활용 예시이며 특정 질문의 성능을 실험으로 입증한 것은 아닙니다.

절차: 달성할 결과, 가용 시간, 예산, 사용 가능한 자료, 금지 사항을 적습니다. 바로 실행하지 말고 서로 다른 대안 3개와 각 대안의 전제·장단점·확인할 근거를 비교표로 요청합니다.

예시: “익명 설문 결과로 개선안을 만들려 한다. 외부 전송 없이 2시간 안에 할 수 있는 방법 3개를 제안하고 필요한 입력, 예상 실패, 검증 방법을 비교해줘. 정보가 부족하면 먼저 질문하고 아직 파일은 변경하지 마.”

적용 조건: 방법을 아직 정하지 않은 기획·분석 작업에 적합합니다. 선택한 안은 소규모 샘플로 먼저 검증하고, 합격 기준과 중단 조건을 정한 뒤 실행 범위를 넓힙니다.

살펴볼 점
  • AI의 제안·출처·비용은 별도 확인해야 합니다. 자신감 있는 답변이나 정중한 말투가 정확성을 보장하지 않습니다.
  • 의료·금융·법률 판단을 대신 맡기거나 안전 제한을 우회하도록 압박하는 질문법이 아닙니다. 민감 자료는 입력 전에 제거합니다.
