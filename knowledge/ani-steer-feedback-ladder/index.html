ani-steer: 교정 사례를 쌓고 필요한 규칙만 붙이는 Claude Code 플러그인

피드백을 곧바로 영구 규칙으로 만들지 않고 사례·교훈·규칙으로 구분한다. 규칙 승격은 사람이 결정하며 외부 판정 모델로 전송되는 대화 범위 확인이 필요하다.

#Claude Code#피드백#메모리#Jev#MIT

무엇을 할 수 있나요?

ani-steer는 Claude Code에서 사용자의 교정을 사례로 보존하고, 비슷한 판단이 반복될 때 교훈과 규칙으로 구분해 관리하는 제작자 공개 플러그인이다. 한 번의 피드백을 모든 상황에 적용해 반대 방향의 오류를 만드는 일을 줄이려는 설계다. Anthropic 공식 제품이 아니라 독립 제작자의 프로젝트다.

제작자 README의 사다리는 사례, 판단, 교훈, 규칙, 원칙, 상위 목표, 근원 욕구로 나뉜다. 교훈까지는 AI가 정리하지만 규칙 이상으로 승격할지는 사용자가 확정한다. 예를 들어 특정 작업에 대한 교정은 우선 그 프로젝트의 사례로 남기고, 반복된다는 이유만으로 전체 프로젝트 공통 규칙으로 확정하지 않는 방식이다.

요청이 들어오면 Jev가 해당되는 규칙을 골라 최대 3개를 붙이고, 교훈은 직접 붙이지 않는다. 확정된 원칙·상위 목표·근원 욕구는 매번 포함된다. README에는 과거 45일의 Claude Code 기록에서 사용자 요청과 앞뒤 대화 일부를 읽어 교정을 찾는 기능과, 프로젝트별 범위를 사용자가 바꾸는 절차가 설명되어 있다. 실제 사용 전에는 판정 결과와 범위가 맞는지 확인해야 한다.

TypeSafe 또는 OpenRouter를 통한 Jev 판정에는 현재 요청, 직전 요청 일부, Claude 답변 끝부분, 프로젝트명, 규칙 문장이 전송된다고 명시되어 있다. 과거 대화 검색은 문맥과 일부 도구명·파일명·명령 앞부분도 보낼 수 있다. 공개 README 전체와 MIT 라이선스를 검토했지만 설치·키 등록·대화 가져오기·코드 실행이나 직접 테스트는 하지 않았다.

살펴볼 점
  • MIT 라이선스이며 복제·수정·배포 시 저작권·허가 고지를 유지해야 한다. 소프트웨어는 무보증으로 제공된다.
  • API 판정 비용과 Claude Code 사용 조건은 별도다. 외부 전송이 없는 순수 로컬 메모리 도구로 소개하면 안 된다.
  • 제작자 문서의 키 저장 경로는 Claude 설정 JSON이다. 채팅에 키를 남기지 않는다는 설명은 키체인 보관이나 암호화 저장을 보장하지 않는다.
  • README에 설명된 동작을 검증한 소개다. 구현 전체의 보안 감사, 호환성·비용 절감·피드백 품질의 실측 검증은 하지 않았다.
